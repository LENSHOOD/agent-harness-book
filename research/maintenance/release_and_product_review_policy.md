# 研究版维护与正式 1.0 发布制度

生效日期：2026-08-28

本制度把第四轮验收报告中的非阻塞建议转成可执行维护流程。它不改变研究版已经通过的结论，但用于防止产品事实、来源状态和审计引用随时间漂移。

## 1. 产品事实月度巡检

每个自然月第一周检查第 13–18 章。负责人逐章读取章首资料截面，复核供应商官方文档、官方仓库 release/commit、安全公告和兼容性说明。若资料截面距计划发布日期超过 45 天，必须在发布前完成复核；超过 90 天而未复核的产品章不得进入正式版本标签。

巡检产生以下记录：检查日期、旧/新版本或网页快照、行为变化、受影响正文、source/evidence/claim 变更、无需修改的理由和复核人。产品名称未变化不代表行为未变化；权限、沙箱、恢复、扩展、遥测和默认工具集属于优先检查面。

## 2. 来源 registry 维护

`metadata_status=verified` 必须同时具备 `accessed_at` 与 `version_or_commit`。`unverified` 来源可以保留为检索 backlog，但不得被新的承重 claim 引用。每次来源状态变化同步更新 `research/evidence/README.md` 中的 `registry-status` 标记；`audit_claim_ledger.py` 负责拒绝状态漂移。

Pi 等由非连续片段合成的引文必须在 locator 中逐段列出行号并标明 `concatenated`。连续原句不得误标为拼接引文。仓库来源优先记录 commit；网页来源记录访问日期与快照日期。

## 3. 正式 1.0 外部盲审门

正式 1.0 至少邀请三类未参与写作的审阅者：企业 Agent 平台工程师、安全或治理专家、熟悉 Agent 研究方法的研究者。审阅者独立收到同一候选 commit、验收清单和证据入口，先提交报告再互相查看，避免意见互相锚定。

盲审至少覆盖事实抽样、责任边界、恢复与 effect 语义、进化评价隔离、案例可执行性和产品版本新鲜度。所有 P0/P1 必须关闭；P2 或建议项可以延期，但需在处置报告中给出 owner、理由和目标版本。最终发布审计绑定被审阅的不可变 commit SHA，而不是分支名。

## 4. 导航短标题规则

当前侧边栏使用完整规范标题。只有真实可用性测试证明长标签影响导航时，才在 `publishing/book_structure.json` 增加 `short_title`；站点从该字段派生，完整 H1 仍由 `title` 提供。禁止重新引入手写侧边栏标题副本。

## 5. 每次公开更新的最小门禁

按顺序运行证据审计、标题结构校验、合并稿构建、PDF 渲染、站点同步和 VitePress 构建。随后检查 PDF 书签、空白页、替换字符、下载 base path、源稿/站点 diff，并栅格化抽查所有发生版面变化的页面。审计报告只在这些检查结束后写 PASS。
