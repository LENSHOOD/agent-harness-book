# 核心论点 v0

1. Agent 的工程能力不是模型单变量，而是模型、Harness、环境和反馈的系统乘积。
2. 生产级 Harness 应保持决策环简单，把复杂度投入上下文、安全、执行、恢复、验证和可观测性。
3. Prompt 是概率性行为引导；权限、沙箱、凭据代理与发布门禁才是确定性控制。
4. 上下文不是越多越好。Harness 的核心工作之一是为每一步编译最小充分工作集。
5. 工具接口是 Agent-Computer Interface，其描述、Schema、错误和反馈质量会改变模型能力上限。
6. 多智能体不是默认升级；只有当上下文隔离、并行或独立验证的收益超过协调成本时才成立。
7. 模型不再调用工具只代表自然终止，不代表任务满足验收条件。完成必须由外部证据判定。
8. 从 LangChain 到现代 Coding Harness 的变化，不是“框架消失”，而是编排复杂度从显式图和链迁移到了环境、上下文和控制面。
9. 下一阶段的竞争核心将从能否调用工具，转向能否持续采集轨迹、归因失败、生成候选改进并安全部署。
10. 自我进化必须被理解为受目标函数、评测集、权限和回滚约束的工程过程，而不是 Agent 任意改写自己。
11. 企业平台应把现有 Agent 作为可替换 runtime，把 SDD、策略、审计、验证和进化建立成供应商无关控制面。
12. 最好的 Harness 不是功能最多，而是在特定任务分布上以最低上下文、权限、成本和协调熵稳定地产生可验证结果。
