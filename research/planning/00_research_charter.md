# 《Agent Harness：从执行脚手架到自我进化系统》研究章程

## 目标

为企业 Agent 平台架构师与高级工程师写一本 6–10 万中文字的体系化技术小书。全书回答五个问题：Harness 从何而来；当代优秀 Harness 如何工作；为什么相同模型在不同 Harness 中表现不同；怎样设计安全、可靠、可验证的企业 Harness；Agent 如何在任务内、跨任务、Harness 和模型四层实现受控进化。

## 已确认的编辑原则

1. 证据驱动但有明确设计立场，并为关键判断提供反方论证。
2. 以能力维度组织正文，以产品作为案例，不写产品说明书。
3. 固定主案例为 Claude Code、OpenAI Codex、Cursor、DeepSeek Harness/DSH；第五案例根据使用规模、技术代表性、社区活跃度与资料质量筛选。
4. 历史从控制循环、BDI、规划与工具使用讲起，经 ReAct、Toolformer、Reflexion、Voyager、AutoGPT、BabyAGI、LangChain/AutoGen，进入 SWE-agent、Aider、OpenHands 与现代产品 Harness。
5. “进化”占全书约 20%–25%，既是独立篇章，也是贯穿可观测、评测、变异、灰度与回滚的横向主线。
6. 以语言无关伪代码、状态机、时序图、协议和数据结构解释实现，不绑定编程语言。
7. 产品事实标注版本或检索日期，并区分官方事实、开源实现、逆向事实、社区推断与作者综合判断。
8. 最终原创产出是一套下一代 Harness 参考架构、成熟度模型、设计检查表与企业演进路线。

## 贯穿案例

- 仓库级软件工程：Issue → 探索 → 修改 → 测试 → PR。
- 企业数据分析 Agent：内部数据、权限审批、长任务、审计。
- 自我进化 Agent：失败轨迹 → 候选变异 → 离线评测 → 灰度 → 固化/回滚。

## 研究边界

正文研究 Agent 产品运行时与周边控制面，不尝试写完整模型训练教科书。模型进化只深入到与 Agent Harness 相关的数据生成、轨迹筛选、蒸馏、强化学习、评测和部署闭环。逆向资料用于理解架构和版本差异，不把无法交叉验证的社区推断写成事实。

## 质量门槛

- 主要章节至少包含官方/原始资料、论文或代码、社区实践三类来源中的两类。
- 全书核心主张尽量由三个相互独立的来源簇支持。
- 每个产品案例都包含能力、实现、取舍、失败模式、演进方向，而非功能罗列。
- 每章至少包含一个反例或边界条件。
- 每个设计建议明确适用条件、替代方案和可验证指标。
- 所有事实主张进入 claim ledger；无支持的事实不得进入最终版。

## 分阶段门禁

1. 研究章程、详细目录、核心论点、来源地图。
2. 全网检索后的证据综述、第五案例选择和目录修订。
3. 按历史、原理、产品、进化、参考架构分篇写作。
4. 全书统一审校、HTML/PDF、决策者精简版。
